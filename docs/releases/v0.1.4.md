# v0.1.4

General deployment workflows beyond containers.

- Directory releases: `std/release` prepares a versioned directory, runs optional build and migration hooks, switches `current` and checks activation, restoring the previous release when activation or health fails. `nrg init --template release` scaffolds one. New optional `keep` prunes old releases after a successful deploy while always retaining the active release and its rollback target.
- Optional framework defaults in `std/release_recipes` (Rails, Django, Next.js, Phoenix, Laravel) and app-scoped toolchains in `std/mise`.
- File transfers and steps: `upload_file`/`download_file` with explicit permissions and byte-count checks; `ssh_step`/`local_step` with named, journaled, redacted execution; preflight capability checks.
- `read_file(path)` for local text configuration (read-only, runs in dry-run), and an optional permissions argument for `write_remote` (e.g. `"0644"` for files a non-root service reads).
- Recipe contracts and `nrg rehearse` for exercising real commands and recovery checks in a disposable local workspace.
- Durable run diagnostics and history; hardened transfers, preflights and execution diagnostics; installer and Homebrew tap fixes.

Behavior changes: none intended for existing scripts. `write_remote` without permissions still writes `0600`; releases are never pruned unless `keep` is set.
