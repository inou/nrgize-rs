# v0.2.0

A smaller tool: one proxy, one way to import the stdlib, one place for secrets, and a dry run that prints a plan. Every item below is a breaking change; the [changelog](https://github.com/inou/nrgize-rs/blob/main/CHANGELOG.md) lists each removed name with its replacement.

- Proxy: Caddy is the only reverse proxy. kamal-proxy, `std/proxy`, `cfg.proxy: "kamal"` and `nrg setup --proxy` are gone.
- Stdlib: import it as `std/X`. `nrg vendor` and the `lib/X` mirror are removed; to change a stdlib function, copy it into your script.
- Secrets: `secret()` reads `$NRG_SECRET_<KEY>` or an age-encrypted `ENC[...]` value in `.energize/secrets[.<dest>]`. `.env`, plaintext file values, `CMD[...]` and `nrg secrets seal` / `unseal` are removed. `nrg secrets encrypt KEY` reads the value from stdin and writes the file, which is now meant to be committed.
- Dry run: `--dry-run` plans mutations and runs reads against the real hosts. It no longer simulates container state, so the `sim_*` builtins are gone, a new container's port shows as `<auto>`, and waits are assumed to pass. Live runs issue the same commands as before.
- New builtins: `container_running`, `container_healthy`, `container_image_id`, `port_open`, `pick_port`, and `http_get(url, headers, timeout_secs)`.
- Docs: design history, review archives and the long roadmap are removed; `docs/safety.md` states the limits that still apply.

## Upgrading

Scripts that only import `std/...` modules, run commands with `ssh_exec` / `local_exec` and do not call `secret()` need no changes.

1. Replace `import "lib/X"` with `import "std/X"` and delete a vendored `lib/` copy of the stdlib.
2. Remove `cfg.proxy`. On hosts that ran kamal-proxy, run `nrg setup` to boot Caddy, then deploy.
3. Move each secret: `printf %s "$VALUE" | nrg secrets encrypt KEY`, then commit `.energize/secrets`.
4. Replace `sim_*` calls using the table in the changelog.
