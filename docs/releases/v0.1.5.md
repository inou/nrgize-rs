# v0.1.5

Hardening, static Linux binaries and documentation that matches the code.

- Static Linux binaries: releases now include `x86_64-unknown-linux-musl` and `aarch64-unknown-linux-musl` archives that run on any distribution. `scripts/install.sh` prefers them on Linux and falls back to the glibc archive only when a release has no musl asset.
- State: writes from nested or backgrounded `nrg` processes no longer lose each other's keys; each reload-mutate-write runs under a short-lived lock on `.energize/state.write.lock`.
- Health checks: `timeout` must be a positive integer or float and is quoted in the remote `curl`; a string could previously reach the shell. Caddy `proxy_maintenance` validates `status_code`.
- Secrets: `secret()` warns when a plaintext secrets file is readable by its group or others, and refuses it under `NRG_STRICT_TRUST=1`. `nrg secrets init` sets key file modes explicitly.
- CLI: `--dest` is one global flag, accepted before or after the subcommand. `--help` and stdlib error messages no longer cite internal review numbers.
- Stdlib: kamal-proxy and Caddy share their container scaffolding in the new internal `std/proxy_common`; `nrg vendor` writes it too.
- Docs: guides, builtin and stdlib references are back in sync with the code and a test keeps them there. New `CHANGELOG.md`.
- Dependencies: rustls, rustls-webpki and webpki-roots updated for RUSTSEC-2026-0346 to -0349, -0381 and -0382.
- Release pipeline: one shared CI gate, and the Homebrew formula bump is opened automatically as a pull request.

Behavior changes: repeating `--dest` with different values is an error. A non-numeric health-check `timeout` and an out-of-range Caddy `status_code` now throw. A group- or world-readable plaintext secrets file prints a warning. Vendored projects that customised `lib/proxy.rhai` or `lib/caddy.rhai` keep working; run `nrg vendor` to pick up `lib/proxy_common.rhai` before re-syncing those files.
