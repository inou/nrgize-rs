# v0.1.2

Security and reliability hardening following the September 5 deployment audit.

- Preserve serving backends after ambiguous proxy switches; journal incomplete transitions and atomically commit release state before cleanup.
- Preserve rollback history and configuration on failed deployments; restore the recorded container runtime during native rollback.
- Enforce HTTPS application ingress in Caddy, including migration of existing listeners, and remove implicit host-wide pruning.
- Use private temporary files for secrets and remote builds; publish decrypted files only after authentication succeeds; improve replay and compensation redaction.
- Bound captured commands and bulk concurrency, use owned per-host deployment locks, and coordinate complete state removal.
- Add destination selection to day-2 commands, embed Bunny, improve Bunny rollback identity and optional revision-aware readiness checks, and strengthen audit history.
- Add Linux/macOS release gates, real age/Caddy fault regressions, pinned build inputs, and release provenance attestations.

Behavior changes: unresolved deployment journals require operator reconciliation; HTTP redirects are not followed by the HTTP builtins; captured commands default to a 600-second deadline and 16 MiB per output stream. Caddy application routes require a domain or separately configured certificates for HTTPS. Relative build contexts remain relative to the invoking working directory.

Some distributed-state, trust-policy, and provider limitations remain. See [the audit remediation record](../audit-2026-09-05/REMEDIATION.md) for the complete finding-by-finding status. This release does not claim distributed crash atomicity or live-fleet certification.
